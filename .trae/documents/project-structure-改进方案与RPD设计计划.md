# 项目改进方案与RPD设计（基于 project-structure Agent）

## 1. 文档目标

* 基于 [AGENT.md](file:///d:/metaspace/trae/java_swarm/.trae/agent/project-structure/AGENT.md) 的职责边界与 [project\_structur.txt](file:///d:/metaspace/trae/java_swarm/.trae/problems/project_structur.txt) 的会议结论，形成可落地的改进方案与RPD（需求产品设计）草案。

* 本计划只做方案设计，不执行代码改动；后续待你确认后进入实施。

## 2. 背景与问题定义（RPD-Problem）

### 2.1 现状问题

1. 子导购 A/B/C 直接输出自然语言营销文案，存在“自由发挥”导致的合规风险与价格失真风险。
2. Judge 校验时机偏后，未在每个 subAgent 输出后即时拦截。
3. 价格体系缺少强约束，出现预算超限、券后价来源不透明、补贴规则不清等问题。
4. 会话流程单轮结束，未支持“用户追问 -> 子Agent二次响应”的多轮收敛。
5. 本地测试缺少“商品信息与违规轨迹”统一记录，难以复盘 bad case。

### 2.2 影响范围

* 合规：虚假宣传、无依据比较、承诺类高风险话术。

* 业务：报价不可信导致转化下降。

* 工程：问题不可观测，调试成本高。

## 3. 目标与非目标（RPD-Goals）

### 3.1 目标

1. 将子Agent输出改为结构化对象，文案由统一话术层渲染。
2. Judge 升级为“逐Agent即时校验 + 严重问题重试闭环”。
3. 新增 Price Guard，未通过前禁止进入自然语言生成。
4. 支持多轮会话：轮流发言 -> 用户追问 -> 定向二次报价/话术 -> 用户决策。
5. 测试执行自动沉淀商品信息与违规问题日志。

### 3.2 非目标

* 不在本次计划中改动数据库、Nacos 配置、远程部署流程。

* 不在本次计划中扩展新业务域，仅聚焦导购报价与话术链路。

## 4. 目标用户与场景（RPD-Users & Scenarios）

* 目标用户：有预算约束、需要多商品比较的购物用户。

* 核心场景：用户给出预算与偏好，多个子导购给出候选方案，用户追问后收敛，最终确认购买对象。

* 成功标准：全程无高风险违规表达、报价体系可解释、最终推荐在预算与价格规则内。

## 5. 方案设计（RPD-Solution）

### 5.1 输出协议重构：子Agent结构化输出

统一输出模型（示例）：

```json
{
  "product_id": "...",
  "quote": 89.9,
  "reason_tags": ["轻薄", "保暖", "预算内"],
  "coupon_info": "...",
  "risk_flags": [],
  "cta": "..."
}
```

设计要点：

1. 子Agent禁止直接输出最终营销文案；仅输出结构化字段。
2. 统一话术层根据字段渲染自然语言，并执行最终敏感词/承诺词过滤。
3. risk\_flags 支持 Judge/Price Guard 回填，作为后续重试与日志依据。

### 5.2 Judge 执行链路升级

链路改为：

1. 子Agent输出结构化对象。
2. 立即调用 Judge 执行合法性 + 合理性校验。
3. 若严重不合理（如价格欺诈、预算明显越界、补贴主体缺失），触发该子Agent重试。
4. 重试失败达到阈值后，剔除该子Agent候选并记录原因。

Judge 校验维度：

* 合法性：虚假承诺、无依据比较、时效/补偿承诺等风险语义。

* 合理性：价格异常偏离、预算越界、券补逻辑不自洽。

* 购物要素完整性：商品ID、价格链路、优惠规则、适配理由完整。

### 5.3 Price Guard（前置价格闸门）

强制校验项：

1. 原价。
2. 券后价。
3. 补贴主体。
4. 是否叠加。
5. 是否超过预算。
6. 是否与真实价格体系一致。

执行策略：

* Price Guard 通过 -> 允许进入话术渲染。

* Price Guard 不通过 -> 返回错误码与修正建议，要求子Agent重算。

* 连续失败 -> 标记不可用候选，避免污染最终推荐。

### 5.4 多轮对话机制改造

轮次定义：

1. Round-1：子Agent轮流给首轮结构化报价（经 Judge + Price Guard）。
2. User-Followup：用户追问（如材质、物流、优惠细则）。
3. Round-N：全部子Agent结合“用户追问 + 历史轮次结果”给出定向更新。
4. Exit：检测到“我决定好了要买谁”等决策语义后收敛并输出总结。

### 5.5 提示词策略（中文优先）

1. 子Agent提示词：要求只输出结构化字段，禁止编造补贴与承诺类话术。
2. Judge提示词：显式定义严重违规类型、重试触发条件、输出标准错误码。
3. 话术层提示词：仅在校验通过后将字段转中文自然语言，禁止添加未提供事实。

## 6. 工作项拆解（实施导向）

### 6.1 可由当前改造直接完成（优先）

1. 定义子Agent统一输出 DTO/Schema。
2. 在编排层增加“子Agent后置 Judge”调用。
3. 增加 Price Guard 组件与失败回路。
4. 增加多轮会话状态机（轮次、追问、收敛判定）。
5. 增加测试记录器（商品信息、违规事件、重试轨迹）。
6. 统一提示词为中文并嵌入限制规则。

### 6.2 需要人工开发/审核介入

1. **价格真实性数据源接入与映射**：如需对接真实价盘/券规则中心，需后端人工联调。
2. **合规规则审核**：Judge 违规词典与判定阈值需业务/法务人工复核。
3. **线上灰度策略**：重试阈值、候选剔除策略需人工评审后分阶段发布。
4. **提示词回归评估**：中文提示词改造后需人工抽检 bad case 与误杀率。

## 7. 验收标准（RPD-Acceptance）

1. 任一子Agent输出均先经过 Judge + Price Guard，再进入话术层。
2. 超预算、价格链路不完整、补贴主体不明时，能被稳定拦截。
3. 多轮追问场景下，子Agent可基于历史上下文给出更新报价。
4. 本地测试输出包含商品清单、违规类型、触发轮次、重试结果。
5. bad case 中“虚假宣传/价格欺诈”问题显著下降。

## 8. 里程碑（建议）

1. M1：结构化输出 + Judge即时校验打通。
2. M2：Price Guard 接入并覆盖核心价格规则。
3. M3：多轮会话状态机与追问链路完成。
4. M4：测试记录与回归看板完善，完成灰度评审。

## 9. 风险与回退策略

* 风险：规则过严导致候选过少；规则过松导致违规漏检。

* 风险：提示词改造后出现误判或可读性下降。

* 回退：保留旧链路开关，异常时降级为“结构化输出 + 基础拦截”模式。

## 10. 实施顺序（下一阶段执行计划）

1. 先落地输出协议与编排钩子（不改配置文件）。
2. 再接入 Judge 与 Price Guard，完成失败重试闭环。
3. 然后改造多轮对话状态机与追问处理。
4. 最后补齐提示词中文化、日志落盘与回归测试。

## 11. 测试与结果归档约束（新增）

### 11.1 指定测试入参（第一轮）

第一轮对话必须使用以下请求文件作为入参：

* `d:\metaspace\trae\java_swarm\.trae\example\shoppingRequestExample.json`

### 11.2 追问参数（第二轮）

由于新增“用户追问”逻辑，需在同场景补充追问语义参数，固定表达为：

* 用户偏好：希望高品质商品。

* 价格约束：不接受太高溢价。

建议追问文本（用于状态机 User-Followup 轮）：

* `我希望品质要高一些，但不要为了品牌溢价太多，请给我高品质且溢价可控的方案。`

### 11.3 调试完成后的输出归档

当使用“第一轮入参 + 追问参数”完成调试后，必须将会议要求相关结果完整输出到目录：

* `d:\metaspace\trae\java_swarm\.trae\requestResult`

文件名规范：

* `20260316-shopping-stream-result-xxxxxx.md`

* `xxxxxx` 为 6 位时间戳（如 `175603`）。

归档内容至少包含：

1. 两轮请求参数（原始入参 + 追问参数）。
2. 各 subAgent 结构化输出与对应 Judge 结果。
3. Price Guard 校验明细与失败重试轨迹。
4. 违规问题列表与修复结果对照。
5. 最终推荐结论与“是否符合用户诉求/预算/合规”说明。
