# 任务执行服务模块设计文档

## 1. 模块概述

任务执行服务模块负责执行用户提交的购物任务和小红书宣传任务。该模块采用极简设计，预置两种任务模板（商品购买模板和小红书宣传贴发布模板），由用户分身智能体根据用户需求自主选择模板并拆解任务清单，全程监督任务完成，无需用户干预中间流程。

## 2. 功能需求

### 2.1 核心功能
- **任务模板管理**: 预置商品购买和小红书宣传两种任务模板
- **任务提交**: 用户点击"开始任务"按钮后，由用户分身智能体自主拆解任务清单并执行
- **状态跟踪**: 实时更新任务整体状态及各子任务执行状态
- **结果展示**: 展示任务执行的完整过程、各子任务结果及最终整体结果
- **任务决策**: 平台不固定任务流程，具体执行的任务清单由用户分身智能体自主决定

### 2.2 预置任务模板

#### 商品购买模板
包含核心任务步骤：
1. 调用商品库查询API，根据用户画像筛选商品
2. 调用SPU-SKU关联查询API，获取目标商品及关联推荐商品
3. 调用竞价查询API，获取不同渠道价格
4. 对比分析数据（价格、规格、竞价优势）
5. 与导购智能体协商价格
6. 提交购买决策供用户确认

#### 小红书宣传贴发布模板
包含核心任务步骤：
1. 调用商品库查询API，获取目标商品详细信息
2. 根据用户画像及商品特点编写宣传文案（适配小红书风格，突出商品优势）
3. 调用小红书token获取API，获取用户账号权限（Demo版手动输入小红书账号密码，预留自动授权接口）
4. 调用小红书发帖API，上传文案及测试图片，执行发帖操作
5. 调用小红书评论查询API，获取帖子评论列表
6. 可根据评论内容，调用评论发布API回复核心评论
7. 监控发帖、评论结果，处理简单异常情况（如token过期、发帖失败，提示用户重新获取token）

### 2.3 任务状态管理
- **PENDING**: 任务已提交，等待执行
- **RUNNING**: 任务正在执行中
- **SUCCESS**: 任务成功完成
- **FAILED**: 任务执行失败

## 3. 技术架构

### 3.1 系统架构
```
任务执行服务
├── Web层 (Spring Boot Controller)
├── 业务逻辑层 (Task Execution Service)
├── 任务模板层 (Task Template Manager)
├── 状态管理层 (Task State Manager)
├── 结果处理层 (Result Processor)
└── 外部服务集成层 (API Registry, Conversation, Prompt Services)
```

### 3.2 技术栈
- **框架**: Spring Boot 3.3.2
- **异步处理**: Spring @Async
- **状态管理**: 数据库 + 缓存
- **外部集成**: REST API调用
- **JSON处理**: Jackson

### 4.1 数据库设计

#### 任务表 (demo_tasks)
```sql
CREATE TABLE demo_tasks (
    task_id VARCHAR(64) PRIMARY KEY COMMENT '任务ID',
    user_id VARCHAR(64) NOT NULL COMMENT '所属用户ID',
    user_agent_id VARCHAR(64) NOT NULL COMMENT '执行任务的智能体ID',
    task_type VARCHAR(32) NOT NULL COMMENT 'PRODUCT_PURCHASE/XIAOHONGSHU_PUBLISH',
    status VARCHAR(32) NOT NULL COMMENT 'PENDING/RUNNING/SUCCESS/FAILED',
    product_result TEXT COMMENT '商品查询结果',
    comparison_result TEXT COMMENT '对比结果',
    negotiation_result TEXT COMMENT '砍价结果',
    xiaohongshu_result TEXT COMMENT '小红书操作结果（含postId、commentId）',
    final_result TEXT COMMENT '最终结果',
    error_message TEXT COMMENT '错误信息',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_user_id(user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

  ```json
      "preferences": ["性价比高", "续航好"]
    }
  }
  ```
- **响应数据**:
  ```json
  {
    "taskId": "task_123456789",

    "userAgentId": "USER_AVATAR-user123-a1b2c3d4",
    "taskType": "PRODUCT_PURCHASE",
    "status": "PENDING",
    "createdAt": "2026-04-06T10:30:00Z"
  }
  ```

- **功能**: 获取任务状态和结果
- **路径参数**:
  - `id`: 任务ID
- **响应数据**:
  ```json
  {
    "taskId": "task_123456789",
    "userId": "user123",
    "userAgentId": "USER_AVATAR-user123-a1b2c3d4",
    "taskType": "PRODUCT_PURCHASE",
    "status": "RUNNING",
    "productResult": "{...}",
    "comparisonResult": "{...}",
    "negotiationResult": "{...}",
    "finalResult": "{...}",
    "errorMessage": "",
    "createdAt": "2026-04-06T10:30:00Z",

  }
  ```

- **功能**: 获取用户的所有任务
- **路径参数**:

  - `pageSize`: 每页条数（默认20）
- **响应数据**:
  ```json
  {
    "tasks": [
      {
        "taskId": "task_123456789",
        "taskType": "PRODUCT_PURCHASE",
        "status": "SUCCESS",
        "createdAt": "2026-04-06T10:30:00Z"
      }

  }
  ```

### 4.3 业务流程设计

#### 4.3.1 任务提交流程
1. 前端调用 `/api/tasks` 接口提交任务
2. 服务端验证参数（userId、userAgentId、taskType）
3. 生成唯一的 `task_id`
4. 在数据库中创建任务记录，状态设为 `PENDING`
5. 异步启动任务执行流程
6. 返回任务创建成功的响应

#### 4.3.2 商品购买任务执行流程
1. **商品查询阶段**:
   - 调用API注册服务的 `search_products` API
   - 根据用户画像中的预算和偏好筛选商品
   - 保存商品查询结果到数据库

2. **SPU-SKU查询阶段**:
   - 调用API注册服务的 `spu_sku_info` API
   - 获取目标商品的SPU-SKU关联信息
   - 获取3个关联推荐商品
   - 保存SPU-SKU查询结果

3. **竞价查询阶段**:
   - 调用API注册服务的 `product_bidding` API
   - 获取不同渠道的竞价数据
   - 保存竞价查询结果

4. **数据分析阶段**:
   - 对比各商品的价格、规格、竞价优势
   - 生成对比分析报告
   - 保存对比结果

5. **价格协商阶段**:
   - 创建对话会话（调用对话管理服务）
   - 发送协商消息给商品导购智能体
   - 接收导购智能体的报价和建议
   - 进行多轮协商（最多3轮）
   - 保存协商结果

6. **结果生成阶段**:
   - 生成最终购买决策
   - 更新任务状态为 `SUCCESS` 或 `FAILED`
   - 保存最终结果

#### 4.3.3 小红书宣传任务执行流程
1. **商品信息获取阶段**:
   - 调用API注册服务的 `search_products` API
   - 获取目标商品详细信息
   - 保存商品信息

2. **文案编写阶段**:
   - 根据用户画像和商品特点生成宣传文案
   - 适配小红书风格（突出商品优势、使用场景）
   - 保存文案内容

3. **Token获取阶段**:
   - 调用API注册服务的 `xh_get_token` API
   - 获取小红书用户token
   - 保存token信息

4. **发帖阶段**:
   - 调用API注册服务的 `xh_publish_post` API
   - 上传文案和测试图片
   - 获取postId
   - 保存发帖结果

5. **评论监控阶段**:
   - 调用API注册服务的 `xh_list_comments` API
   - 获取帖子评论列表
   - 分析评论内容
   - 保存评论结果

6. **评论回复阶段**:
   - 根据评论内容决定是否需要回复
   - 调用API注册服务的 `xh_publish_comment` API
   - 发布回复评论
   - 保存回复结果

7. **结果生成阶段**:
   - 生成最终宣传结果报告
   - 更新任务状态为 `SUCCESS` 或 `FAILED`
   - 保存最终结果

#### 4.3.4 状态更新流程
1. 任务开始执行时，更新状态为 `RUNNING`
2. 每个子任务完成后，更新相应的结果字段
3. 任务完成后，更新状态为 `SUCCESS` 或 `FAILED`
4. 如果发生异常，记录错误信息并更新状态为 `FAILED`

### 4.5 异常处理

#### 4.5.1 异常类型
- **参数验证异常**: 无效的taskType、空的userId等
- **任务不存在异常**: 查询或操作不存在的任务
- **API调用异常**: 外部API调用失败
- **对话异常**: 会话创建或消息发送失败
- **业务逻辑异常**: 任务执行过程中的业务错误
- **系统异常**: 数据库操作失败、网络错误等

#### 4.5.2 错误码设计
| 错误码 | 错误信息 | HTTP状态码 |
|--------|----------|------------|
| 6001 | 无效的任务类型 | 400 |
| 6002 | 用户ID不能为空 | 400 |
| 6003 | 任务不存在 | 404 |
| 6004 | 任务状态冲突 | 409 |
| 6005 | API调用失败 | 502 |
| 6006 | 对话服务不可用 | 503 |
| 6007 | 任务执行失败 | 500 |

## 6. 安全考虑

### 6.1 安全措施
- **用户隔离**: 严格验证用户ID，防止跨用户任务操作
- **输入验证**: 严格验证所有输入参数
- **敏感信息**: 不在日志中记录敏感的API参数
- **访问控制**: 只有任务所有者才能查询和操作任务
- **错误信息**: 不暴露内部系统信息

### 6.2 权限控制
- Demo版本简化权限控制，所有任务操作都需要提供有效的userId
- 不同用户的任务完全隔离
- 敏感操作（如小红书发帖）需要有效的access_token
