# 用户画像服务模块设计文档

## 1. 模块概述

用户画像服务模块负责处理用户上传的个人文档，通过阿里云百炼大模型服务解析并生成结构化的用户画像数据。该模块是整个多智能体电商系统的基础，为后续的智能体行为决策提供个性化依据。

## 2. 功能需求

### 2.1 核心功能
- **手动登录支持**: 接收前端传入的user_id，无需验证直接使用
- **文档上传处理**: 支持PDF和TXT格式文档上传
- **文档存储管理**: 将上传的文档存储在服务器本地文件系统
- **文档内容解析**: 调用阿里云百炼文档解析API提取纯文本内容
- **用户画像生成**: 调用大模型将纯文本转换为结构化JSON格式的用户画像
- **画像数据查询**: 提供当前用户画像数据的查询接口

### 2.2 数据结构
用户画像JSON结构：
```json
{
  "name": "张三",
  "age": 28,
  "occupation": "程序员", 
  "budget": 3000,
  "preferences": ["性价比高", "续航好", "拍照清晰"],
  "dislikes": ["高价低配", "系统卡顿"]
}
```

### 3.1 系统架构
```
用户画像服务
```

- **数据库**: MySQL 8.0.36
- **HTTP客户端**: OkHttp 4.11.0

## 4. 详细设计

### 4.1 数据库设计

#### 用户画像表 (user_profiles)
```sql
CREATE TABLE user_profiles (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id VARCHAR(64) NOT NULL COMMENT '手动输入的用户ID',
    file_name VARCHAR(256) NOT NULL COMMENT '原文件名',
    file_path VARCHAR(512) NOT NULL COMMENT '本地存储路径',
    file_size BIGINT NOT NULL COMMENT '文件大小(字节)',
    content TEXT COMMENT '文档纯文本内容',
    structured_content JSON COMMENT '结构化用户画像',
    status VARCHAR(32) NOT NULL DEFAULT 'UPLOADED' COMMENT 'UPLOADED/PROCESSING/READY/ERROR',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_user_id(user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 4.2 API接口设计

#### 4.2.1 通用响应格式
```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

#### 4.2.2 具体接口

**POST /api/profiles/upload**
- **功能**: 上传用户画像文档
- **请求参数**:
  - `userId`: string, 必填, 用户ID
  - `file`: multipart/form-data, 必填, PDF或TXT文件
- **响应数据**:
  ```json
  {
    "profileId": 123,
    "userId": "user123",
    "fileName": "profile.pdf",
    "status": "UPLOADED"
  }
  ```

**GET /api/profiles/current**
- **功能**: 获取当前用户画像
- **请求参数**:
  - `userId`: string, 必填, 用户ID (通过Header或Query Parameter传递)
- **响应数据**:
  ```json
  {
    "profileId": 123,
    "userId": "user123", 
    "fileName": "profile.pdf",
    "structuredContent": {
      "name": "张三",
      "age": 28,
      "occupation": "程序员",
      "budget": 3000,
      "preferences": ["性价比高", "续航好", "拍照清晰"],
      "dislikes": ["高价低配", "系统卡顿"]
    },
    "status": "READY"
  }
  ```

### 4.3 业务流程设计

#### 4.3.1 文档上传流程
1. 前端调用 `/api/profiles/upload` 接口上传文件
2. 服务端验证文件格式（仅允许PDF、TXT）
3. 生成存储路径：`/data/profiles/{user_id}/{original_filename}`
4. 保存文件到本地存储
5. 在数据库中创建记录，状态设为 `UPLOADED`
6. 异步启动文档解析任务
7. 返回成功响应

#### 4.3.2 文档解析流程
1. 启动异步任务处理新上传的文档
2. 更新数据库状态为 `PROCESSING`
3. 调用阿里云百炼文档解析API提取纯文本
4. 调用通义千问3.5大模型，使用预设提示词将纯文本转换为结构化JSON
5. 验证生成的JSON格式是否符合预期结构
6. 更新数据库中的 `content` 和 `structured_content` 字段
7. 更新状态为 `READY` 或 `ERROR`

#### 4.3.3 画像查询流程
1. 前端调用 `/api/profiles/current` 接口
2. 服务端根据 `userId` 查询数据库
3. 如果状态为 `READY`，返回完整的画像数据
4. 如果状态为 `PROCESSING`，返回处理中状态
5. 如果状态为 `ERROR`，返回错误信息
6. 如果不存在记录，返回空数据

### 4.5 异常处理

#### 4.5.1 异常类型
- **文件格式异常**: 上传非PDF/TXT文件
- **文件大小异常**: 文件过大（>10MB）
- **存储异常**: 本地存储写入失败
- **API调用异常**: 阿里云百炼API调用失败
- **解析异常**: 大模型返回格式不符合预期
- **数据库异常**: 数据库操作失败

#### 4.5.2 错误码设计
| 错误码 | 错误信息 | HTTP状态码 |
|--------|----------|------------|
| 1001 | 不支持的文件格式 | 400 |
| 1002 | 文件大小超出限制 | 400 |
| 1003 | 文件存储失败 | 500 |
| 1004 | 文档解析服务不可用 | 503 |
| 1005 | 用户画像生成失败 | 500 |
| 1006 | 用户ID不能为空 | 400 |

## 5. 配置管理

### 5.1 应用配置
```properties
# 文件存储配置
profile.storage.base-path=/data/profiles
profile.storage.max-file-size=10485760 # 10MB

# 阿里云百炼配置
alibaba.bailian.api-key=${BAILIAN_API_KEY}
alibaba.bailian.endpoint=https://dashscope.aliyuncs.com/api/v1

# 大模型配置
llm.model=qwen-max
llm.timeout=30000
```

### 5.2 环境变量
- `BAILIAN_API_KEY`: 阿里云百炼API密钥
- `PROFILE_STORAGE_PATH`: 文件存储基础路径（可选，默认为/data/profiles）

## 6. 安全考虑

### 6.1 安全措施
- **文件类型验证**: 严格限制只允许PDF和TXT格式
- **文件名清理**: 防止路径遍历攻击，清理特殊字符
- **API密钥保护**: 通过环境变量配置，不在代码中硬编码
- **输入验证**: 对user_id进行长度和字符验证
- **错误信息脱敏**: 不在错误响应中暴露敏感信息

### 6.2 权限控制
- Demo版本简化权限控制，所有操作基于user_id进行隔离
- 不同用户的文件和数据完全隔离
- 无跨用户数据访问权限

## 7. 性能优化
