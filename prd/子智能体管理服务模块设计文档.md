# 子智能体管理服务模块设计文档

## 1. 模块概述

子智能体管理服务模块负责管理用户创建的智能体实例，包括智能体的创建、部署、启动、停止和删除等全生命周期管理。该模块通过调用阿里云ACK（容器服务Kubernetes版）API来动态部署智能体Pod，并确保智能体能够自动注册到Nacos服务发现中心。

## 2. 功能需求

### 2.1 核心功能

- **智能体类型管理**: 支持两种预定义的智能体类型
  - 用户分身智能体（USER\_AVATAR）：代表用户执行任务，调用API和其他智能体
  - 商品导购智能体（PRODUCT\_GUIDE）：提供商品咨询和价格谈判服务
- **智能体创建**: 根据用户选择的类型和名称创建智能体实例
- **K8s部署管理**: 调用阿里云ACK API创建Deployment和Service
- **状态监控**: 监听Pod状态变化，更新数据库中的智能体状态
- **生命周期管理**: 支持启动、停止、删除智能体实例
- **Nacos集成**: 确保智能体启动后能自动注册到Nacos

### 2.2 智能体标识规则

- **instance\_id**: `{user_id}-{随机字符串}-yyyyMMDD-version号 `(唯一标识)
- **service\_name**: `{agent_type}-{user_id}` (Nacos服务名)

### 2.3 状态管理

- **0-PENDING**: 智能体已创建，等待部署
- **1-RUNNING**: 智能体已成功部署并运行
- **2-STOPPED**: 智能体已停止
- **3-ERROR**: 部署或运行过程中发生错误
- **4-DELETED**: 智能体已被删除

## 3. 技术架构

### 3.1 系统架构

```
子智能体管理服务
├── Web层 (Spring Boot Controller)
├── 业务逻辑层 (Agent Management Service)
├── K8s客户端层 (Fabric8 Kubernetes Client)
├── Nacos集成层 (服务注册/发现)
├── 数据访问层 (Repository)
└── 异步任务层 (状态监控)
```

### 3.2 技术栈

- **框架**: Spring Boot 3.3.2
- **K8s客户端**: Fabric8 Kubernetes Client 6.12.0
- **服务发现**: Nacos 2.4.2
- **数据库**: MySQL 8.0.36
- **异步处理**: Spring @Async

### 4.1 数据库设计

#### 智能体实例表 (agent\_instances)

```sql
CREATE TABLE agent_instances (
    instance_id VARCHAR(64) PRIMARY KEY COMMENT '智能体实例ID',
    user_id VARCHAR(64) NOT NULL COMMENT '所属用户ID',
    agent_type VARCHAR(32) NOT NULL COMMENT 'USER_AVATAR/PRODUCT_GUIDE',
    name VARCHAR(128) NOT NULL COMMENT '智能体名称',
    status TINYINT NOT NULL COMMENT '0-PENDING/1-RUNNING/2-STOPPED/3-ERROR/4-DELETED',
    service_name VARCHAR(128) NOT NULL COMMENT 'Nacos服务名',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_user_id(user_id),
    INDEX idx_status(status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 4.3 业务流程设计

#### 4.3.1 智能体创建流程

1. 前端调用 `/api/agents` 接口创建智能体
2. 服务端验证参数（userId、agentType、name）
3. 生成唯一的 `instance_id` 和 `service_name`
4. 在数据库中创建记录，状态设为 `PENDING`
5. 异步调用阿里云ACK API创建Deployment和Service
6. 启动状态监控任务，监听Pod状态变化
7. 返回创建成功的响应

#### 4.3.2 K8s资源创建流程

1. **准备K8s部署YAML配置**
   - 在内部预置完整的Deployment和Service YAML模板
   - **服务名可编辑**: 支持通过`service_name`参数自定义服务名称
   - **其他属性保留修改入口**: CPU、Memory、健康检查路径等配置项预留扩展点，但Demo阶段使用默认值
   - 使用Java 21基础镜像
   - 设置环境变量（user\_id、agent\_type、service\_name、nacos\_server\_addr等）
2. **Nacos配置上传**
   - 根据智能体类型（USER\_AVATAR/PRODUCT\_GUIDE）生成对应的Nacos配置
   - 调用Nacos API将配置上传到指定的dataId和group
   - 配置内容包含智能体运行所需的参数、提示词引用、API地址等
3. **构建并应用K8s资源**
   - 基于YAML模板和用户参数构建最终的Deployment配置
   - 构建对应的Service配置（ClusterIP类型，端口8080）
   - 调用Fabric8 Kubernetes Client创建资源
   - 记录操作日志和资源配置详情

#### 4.3.3 状态监控流程

1. 启动定时任务，每5秒检查一次Pod状态
2. 查询对应Deployment下的Pod列表
3. 如果Pod状态为Running：
   - 更新数据库中的 `pod_ip` 字段
   - 更新状态为 `RUNNING`
   - 停止监控任务
4. 如果Pod状态为Error或Failed：
   - 更新状态为 `ERROR`
   - 记录错误信息
   - 停止监控任务
5. 如果超过5分钟仍未达到Running状态：
   - 更新状态为 `ERROR`
   - 停止监控任务

#### 4.3.4 智能体启停流程

**启动流程**:

1. 验证智能体存在且状态为STOPPED
2. 调用K8s API恢复Deployment的副本数为1
3. 重新启动状态监控任务
4. 更新状态为PENDING

**停止流程**:

1. 验证智能体存在且状态为RUNNING
2. 调用K8s API将Deployment的副本数设置为0
3. 更新状态为STOPPED
4. 清理pod\_ip字段

#### 4.3.5 智能体删除流程

1. 验证智能体存在
2. 如果状态为RUNNING，先停止智能体
3. 调用K8s API删除Deployment和Service
4. 从数据库中删除记录
5. 清理相关资源

### 4.5 异常处理

#### 4.5.1 异常类型

- **参数验证异常**: 无效的agentType、空的userId等
- **K8s操作异常**: ACK API调用失败、资源创建失败
- **Nacos配置异常**: Nacos配置上传失败、配置格式错误
- **状态冲突异常**: 对STOPPED的智能体执行stop操作
- **权限异常**: 用户尝试操作其他用户的智能体
- **资源不足异常**: K8s集群资源不足
- **网络异常**: 与ACK或Nacos通信失败

#### 4.5.2 错误码设计

| 错误码  | 错误信息        | HTTP状态码 |
| ---- | ----------- | ------- |
| 2001 | 无效的智能体类型    | 400     |
| 2002 | 用户ID不能为空    | 400     |
| 2003 | 智能体名称不能为空   | 400     |
| 2004 | 智能体不存在      | 404     |
| 2005 | 状态操作冲突      | 409     |
| 2006 | K8s操作失败     | 500     |
| 2007 | Nacos配置上传失败 | 500     |
| 2008 | 资源不足        | 503     |
| 2009 | 网络连接失败      | 503     |

## 6. 安全考虑

### 6.1 安全措施

- **用户隔离**: 严格验证用户ID，防止跨用户操作
- **K8s权限**: 使用最小权限原则配置ServiceAccount
- **网络策略**: 限制智能体Pod的网络访问范围
- **输入验证**: 严格验证所有输入参数
- **日志脱敏**: 不在日志中记录敏感信息

### 6.2 权限控制

- **操作权限**: 只有智能体的所有者才能进行操作
- **K8s权限**: 使用RBAC限制对K8s资源的操作权限
- **API权限**: 所有API都需要提供有效的userId
