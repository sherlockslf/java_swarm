# 对话管理服务模块设计文档

## 1. 模块概述

对话管理服务模块负责管理用户、用户分身智能体和商品导购智能体之间的会话和消息交互。该模块支持多会话并行处理，存储所有智能体间的消息，并提供会话历史查询功能，确保多智能体协同工作的完整性和可追溯性。

## 2. 功能需求

### 2.1 核心功能
- **会话管理**: 支持用户及用户分身智能体同时发起多个会话，与不同智能体进行交互
- **消息存储**: 存储所有智能体的输出消息，包含智能体ID、智能体类型、输出文本、时间戳
- **会话查询**: 支持按会话ID查询所有历史消息
- **消息格式**: 消息内容为纯文本，不支持其他格式
- **会话唯一性**: 确保每个会话的唯一标识

### 2.2 会话标识规则
- **会话ID**: 字符串格式，由系统生成唯一标识
- **参与方**: 用户、用户分身智能体、商品导购智能体

### 2.3 职责划分
- **用户**: 负责核心决策、支付等必要操作，提供初始用户输入
- **用户分身智能体**: 负责任务拆解、多智能体交互、任务分发以及监督任务完整执行，无需用户干预中间流程
- **商品导购智能体**: 提供商品咨询和价格谈判服务

## 3. 技术架构

### 3.1 系统架构
```
对话管理服务
├── Web层 (Spring Boot Controller)
├── 业务逻辑层 (Conversation Service)
├── 数据访问层 (Repository)
├── 消息处理层 (Message Processor)
└── 缓存层 (可选，Redis)
```

### 3.2 技术栈
- **框架**: Spring Boot 3.3.2
- **数据库**: MySQL 8.0.36
- **缓存**: Redis (可选)
- **消息格式**: 纯文本
- **并发处理**: Spring @Async

## 4. 详细设计

### 4.1 数据库设计

根据需求规格，对话管理服务包含两张核心表：

#### 会话表 (sessions)
```sql
CREATE TABLE sessions (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '自增主键',
    user_id BIGINT UNSIGNED NOT NULL COMMENT '用户ID（长整型，无负数）',
    session_id VARCHAR(128) NOT NULL COMMENT '会话ID（字符串）',
    session_name VARCHAR(256) NOT NULL COMMENT '会话名称',
    user_input TEXT COMMENT '用户输入',
    timestamp BIGINT NOT NULL COMMENT '时间戳（Unix时间戳）',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_user_id(user_id),
    INDEX idx_session_id(session_id),
    UNIQUE KEY uk_session_id(session_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

#### 对话表 (conversations)
```sql
CREATE TABLE conversations (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '自增主键',
    session_id VARCHAR(128) NOT NULL COMMENT '会话ID（与sessions表对应）',
    agent_id VARCHAR(128) NOT NULL COMMENT '智能体ID（字符串）',
    agent_type VARCHAR(64) NOT NULL COMMENT '智能体类型（USER_AVATAR/PRODUCT_GUIDE）',
    output_text TEXT NOT NULL COMMENT '输出文本',
    timestamp BIGINT NOT NULL COMMENT '时间戳（Unix时间戳）',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_session_id(session_id),
    INDEX idx_agent_id(agent_id),
    INDEX idx_timestamp(timestamp),
    FOREIGN KEY (session_id) REFERENCES sessions(session_id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 4.3 API接口设计

#### 4.3.1 通用响应格式
```json

  "message": "success",
  "data": {}
}
```

#### 4.3.2 具体接口

**POST /api/sessions/generate-id**
- **功能**: 创建会话ID（仅生成ID，不保存完整信息）
- **请求参数**:
  ```json
  {
    "userId": 123456789
  }
  ```
- **响应数据**:
  ```json
  {
    "sessionId": "sess_123456789_a1b2c3d4"
  }
  ```

**PUT /api/sessions/{sessionId}**
- **功能**: 保存/更新会话信息（会话ID已创建）
- **路径参数**:
  - `sessionId`: 会话ID
- **请求参数**:
  ```json
  {
    "userId": 123456789,
    "sessionName": "iPhone 15 Pro 购物咨询",
    "userInput": "我想买一款性价比高的手机，预算3000元左右"
  }
  ```
- **响应数据**:
  ```json
  {
    "sessionId": "sess_123456789_a1b2c3d4",
    "userId": 123456789,
    "sessionName": "iPhone 15 Pro 购物咨询",
    "userInput": "我想买一款性价比高的手机，预算3000元左右",
    "timestamp": 1712400000
  }
  ```

**POST /api/conversations/batch**
- **功能**: 批量保存对话信息
- **请求参数**:
  ```json
  {
    "sessionId": "sess_123456789_a1b2c3d4",
    "conversations": [
      {
        "agentId": "USER_AVATAR-user123-a1b2c3d4",
        "agentType": "USER_AVATAR",
        "outputText": "好的，我会为您寻找符合预算的手机推荐。"
      },
      {
        "agentId": "PRODUCT_GUIDE-user123-b2c3d4e5",
        "agentType": "PRODUCT_GUIDE", 
        "outputText": "我推荐iPhone 15 Pro，性价比很高。"
      }
    ]
  }
  ```
- **响应数据**:
  ```json
  {
    "savedCount": 2,
    "conversationIds": [12345, 12346],
    "sessionId": "sess_123456789_a1b2c3d4"
  }
  ```

**GET /api/sessions/user/{userId}**
- **功能**: 根据用户ID查询会话列表
- **路径参数**:
  - `userId`: 用户ID（长整型）
- **查询参数**:
  - `pageNum`: 页码（可选，默认1）
  - `pageSize`: 每页条数（可选，默认20，最大50）
- **响应数据**:
  ```json
  {
    "sessions": [
      {
        "sessionId": "sess_123456789_a1b2c3d4",
        "userId": 123456789,
        "sessionName": "iPhone 15 Pro 购物咨询",
  ```

### 4.4 业务流程设计

#### 4.4.1 创建会话ID流程
1. 任务执行服务调用 `/api/sessions/generate-id` 接口
2. 服务端验证userId参数有效性
3. 生成唯一的 `session_id`（格式：`sess_{userId}_{随机字符串}`）
4. 返回生成的会话ID

#### 4.4.2 保存会话信息流程
1. 任务执行服务调用 `/api/sessions/{sessionId}` 接口（PUT方法）
2. 服务端验证会话ID存在且参数有效（userId、sessionName、userInput）
3. 获取当前Unix时间戳
4. 在sessions表中更新/插入会话记录
5. 返回完整的会话信息

#### 4.4.3 批量保存对话信息流程
1. 任务执行服务调用 `/api/conversations/batch` 接口
2. 服务端验证会话存在且对话消息列表非空
3. 遍历对话消息列表，为每条消息：
   - 获取当前Unix时间戳
   - 在conversations表中插入对话记录
4. 返回批量保存结果（保存数量、生成的对话ID列表）

#### 4.4.4 根据用户ID查询会话列表流程
1. 前端调用 `/api/sessions/user/{userId}` 接口
2. 服务端根据userId查询所有会话
3. 按timestamp降序排列（最新会话在前）
4. 支持分页查询
5. 返回会话列表

#### 4.4.5 根据会话ID查询对话详情流程
1. 前端或服务调用 `/api/conversations/session/{sessionId}` 接口
2. 服务端验证会话存在
3. 查询conversations表，按timestamp排序
4. 支持分页查询
5. 返回对话消息列表

### 4.6 异常处理

#### 4.6.1 异常类型
- **参数验证异常**: 无效的userId、空的sessionName等
- **会话不存在异常**: 查询或添加对话时会话不存在
- **权限异常**: 用户尝试访问其他用户的会话
- **数据库异常**: 数据库操作失败
- **消息过长异常**: 输出文本超出限制

#### 4.6.2 错误码设计
| 错误码 | 错误信息 | HTTP状态码 |
|--------|----------|------------|
| 4001 | 用户ID不能为空 | 400 |
| 4002 | 会话名称不能为空 | 400 |
| 4003 | 输出文本不能为空 | 400 |
| 4004 | 输出文本超出长度限制 | 400 |
| 4005 | 会话不存在 | 404 |
| 4006 | 无权访问此会话 | 403 |
| 4007 | 数据库操作失败 | 500 |

## 6. 安全考虑

### 6.1 安全措施
- **用户隔离**: 严格验证用户ID，防止跨用户会话访问
- **输入验证**: 严格验证所有输入参数长度和格式
- **SQL注入防护**: 使用参数化查询
- **XSS防护**: 对输出文本进行HTML转义（如果前端需要）
- **敏感信息**: 不在日志中记录完整的对话内容

### 6.2 权限控制
- **会话访问**: 只有会话所有者才能访问会话和对话
- **对话添加**: 任何智能体都可以添加对话消息（通过任务执行服务）
- **API权限**: 所有API都需要提供有效的userId或sessionId
