# 商品信息系统模块设计文档

## 1. 模块概述

商品信息系统模块负责提供商品相关的数据查询服务，包括商品库信息查询、SPU-SKU层级关系查询和商品竞价信息查询。该模块为用户分身智能体的购物任务提供核心数据支持，确保智能体能够根据用户画像中的预算和偏好，筛选合适的商品并进行价格对比分析。

## 2. 功能需求

### 2.1 核心功能
- **商品库信息查询**: 支持按关键词模糊查询商品，返回商品完整基础信息
- **SPU-SKU层级关系查询**: 明确SPU（标准化产品单元）与SKU（库存单位）的关联关系
- **商品竞价信息查询**: 针对单个商品，返回不同渠道的竞价数据
- **关联推荐**: 自动推荐3个同品类、同价位的关联商品
- **数据联动**: 与用户画像联动，优先展示符合条件的商品

### 2.2 查询功能详细说明

#### 商品库内信息查询
- **查询方式**: 支持按关键词模糊查询
- **返回内容**: 商品完整基础信息（名称、价格、配置、图片、库存状态）
- **品类限制**: Demo版仅支持手机品类查询
- **用户画像联动**: 根据用户画像中的预算、偏好，优先展示符合条件的商品

#### SPU-SKU层级关系查询
- **查询方式**: 根据SPU ID查询
- **返回内容**: 
  - SPU基础信息（名称、描述、主图）
  - 该SPU下所有SKU信息（SKU ID、规格、价格、库存）
  - 自动返回3个关联推荐商品（同品类、同价位）
- **规格差异说明**: 清晰说明各SKU规格差异及推荐理由

#### 竞价信息查询
- **查询方式**: 根据商品ID查询
- **返回内容**: 不同渠道的竞价数据，包含：
  - 渠道名称
  - 报价
  - 优惠力度
  - 发货时效
- **用途**: 为用户分身智能体与导购智能体砍价、选择最优购买渠道提供依据

### 2.3 数据关联逻辑
- **商品库信息与智能体任务联动**: 用户分身智能体执行购物任务时，自动调用商品信息相关API，将查询结果同步给商品导购智能体，用于价格协商和推荐
- **SPU-SKU数据与用户画像联动**: 根据用户画像中的预算、偏好，优先展示符合条件的SKU及关联推荐商品，提升任务执行效率

## 3. 技术架构

### 3.1 系统架构
```
商品信息系统
├── Web层 (Spring Boot Controller)
├── 业务逻辑层 (Product Service)
├── 数据访问层 (Repository)
├── 缓存层 (Redis)
├── 搜索引擎层 (可选，Elasticsearch)
└── 数据同步层 (Data Synchronization)
```

### 3.2 技术栈
- **框架**: Spring Boot 3.3.2
- **数据库**: MySQL 8.0.36
- **缓存**: Redis
- **搜索**: MySQL全文索引（Demo版）
- **JSON处理**: Jackson

#### 4.2.2 具体接口

**GET /api/products/hot**
- **功能**: 查询热门手机
- **查询参数**: 无
- **响应数据**:
  ```json

          "color": "黑色",
          "cpu": "A17 Pro"
        },
        "mainImageUrl": "https://example.com/iphone15.jpg",
        "stockQuantity": 100
      }
    ]
  }
  ```

**GET /api/products/search**
- **功能**: 商品库信息查询
- **查询参数**:
  - `keyword`: string, 可选, 商品关键词
  - `category`: string, 可选, 品类（默认"phone"）
  - `minPrice`: number, 可选, 最低价格
  - `maxPrice`: number, 可选, 最高价格
  - `pageNum`: integer, 可选, 页码（默认1）
  - `pageSize`: integer, 可选, 每页条数（默认20，最大50）
- **响应数据**:
  ```json
  {

    "total": 100,
    "pageNum": 1,
    "pageSize": 20
  }
  ```

### 4.3 业务流程设计

#### 4.3.1 商品搜索流程
1. 接收搜索请求（关键词、价格范围、分页参数）
2. 构建SQL查询条件
3. 执行MySQL全文搜索或普通查询
4. 应用用户画像过滤（如果提供了userId）
5. 分页返回商品列表

#### 4.3.2 SPU-SKU查询流程
1. 根据SPU ID查询SPU基本信息
2. 查询该SPU下的所有SKU
3. 基于SPU信息生成3个关联推荐商品
4. 返回完整的SPU-SKU关联信息

#### 4.3.3 竞价查询流程
1. 根据商品ID查询有效的竞价信息
2. 过滤已过期的竞价记录
3. 按报价从低到高排序
4. 返回竞价信息列表

#### 4.3.4 关联推荐算法
1. **同品类**: 选择相同category的商品
2. **同价位**: 价格在目标商品±20%范围内
3. **相似度计算**: 基于品牌、规格、用户评价等维度
4. **排序**: 按相似度分数降序排列，取前3个

#### 4.3.5 用户画像联动流程
1. 如果请求中包含userId，调用用户画像服务获取用户画像
2. 提取用户的预算范围（budget字段）
3. 提取用户的偏好（preferences字段）
4. 在商品搜索结果中，优先展示符合预算和偏好的商品
5. 对不符合偏好的商品进行降权或过滤

### 4.5 异常处理

#### 4.5.1 异常类型
- **参数验证异常**: 无效的查询参数、空的SPU ID等
- **商品不存在异常**: 查询的商品、SPU或SKU不存在
- **数据库异常**: 数据库操作失败
- **搜索异常**: 全文搜索失败
- **缓存异常**: Redis操作失败

#### 4.5.2 错误码设计
| 错误码 | 错误信息 | HTTP状态码 |
|--------|----------|------------|
| 7001 | 无效的商品ID | 400 |
| 7002 | SPU ID不能为空 | 400 |
| 7003 | 商品不存在 | 404 |
| 7004 | SPU不存在 | 404 |
| 7005 | 数据库查询失败 | 500 |
| 7006 | 搜索服务不可用 | 503 |

## 6. 安全考虑

### 6.1 安全措施
- **输入验证**: 严格验证所有查询参数
- **SQL注入防护**: 使用参数化查询
- **XSS防护**: 对商品描述等文本内容进行HTML转义
- **敏感信息**: 不在日志中记录完整的商品数据
- **访问控制**: 所有API都需要有效的调用权限

### 6.2 权限控制
- Demo版本简化权限控制，所有商品查询API都是公开的
- 敏感操作（如商品管理）不在Demo范围内
